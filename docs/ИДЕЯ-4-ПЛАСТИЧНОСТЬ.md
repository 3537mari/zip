# Идея 4. Пластичность — авто-оптимизация горячих путей

## Основание

В мозге нейроны усиливают часто используемые связи (синаптическая
пластичность). Аналогично, ZIP автоматически оптимизирует горячие
функции.

## Синтаксис

```zip
@пластичность(порог = 1000)
функция моя_функция(аргументы) { ... }
```

Параметр `порог` — число вызовов, после которого функция считается горячей
(по умолчанию 1000).

## Как работает

1. При каждом вызове функции счётчик увеличивается (VM / IR).
2. При достижении порога функция помечается как «горячая».
3. Компилятор перекомпилирует её с агрессивной оптимизацией
   (`hot` / `noinline` в LLVM, расширенные проходы).
4. VM планирует JIT-замену интерпретации на нативный код
   (MVP: лог `[JIT]`; полный ORC — следующий шаг).

## Прирост производительности

| Режим | Скорость |
|-------|----------|
| До оптимизации | интерпретация байт-кода |
| После (цель) | нативный код (×50–100 относительно VM) |

## Пример

См. `examples/пластичность_демо.zip`:

```zip
@пластичность(порог = 100)
функция сложная_математика(х) {
    сумма = 0
    для и в 0..х {
        сумма = сумма + и * и
    }
    возврат(сумма)
}

функция главная() {
    результат = 0
    для и в 0..1000 {
        результат = сложная_математика(100)
    }
    ПечатьЧисло(результат)
}
```

Запуск через VM:

```bash
zipc examples/пластичность_демо.zip -o пластичность --байткод
zip-vm пластичность.zipc
```

Ожидаемый лог:

```
🔥 Функция N (сложная_математика) стала горячей (100 вызовов, порог 100)
[JIT] Планирование перекомпиляции функции N («сложная_математика»)
```
