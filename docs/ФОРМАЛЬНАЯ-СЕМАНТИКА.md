# Формальная семантика ZIP

Математическая модель исполнения байт-кода ZIP v3 (ZIPB) и инварианты ядра.

## 1. Модель значений

Пусть V — множество всех значений ZIP:

`
V ::= Ничто
    | Целое(i64)
    | Вещественное(f64)
    | Строка(UTF8)
    | Флаг({true, false})
    | Множество(V*)
    | Нечто(V)
    | Успех(V)
    | Ошибка(Строка)
    | Совершенное(V)
`

## 2. Состояние программы

Состояние σ = (S, R, K):

- S — стек значений (S ∈ V*)
- R — регистры (R: ℕ → V)
- K — стек вызовов (K = [F₁, F₂, …])

Каждый кадр F содержит: идентификатор функции, локальные регистры, указатель инструкции.

## 3. Отношения переходов

Семантика описывается отношением:

`
⟨инструкция, σ⟩ → σ'
`

### PUSH_I64

`
⟨PushI64(n), (S, R, K)⟩ → (S · Целое(n), R, K)
`

### ADD

`
⟨Add, (S · Целое(a) · Целое(b), R, K)⟩ → (S · Целое(a + b), R, K)
⟨Add, (S · Вещественное(a) · Целое(b), R, K)⟩ → (S · Вещественное(a + b), R, K)
`

### LOAD / STORE

`
⟨Load(i), (S, R, K)⟩ → (S · R(i), R, K)
⟨Store(i), (S · v, R, K)⟩ → (S, R[i ↦ v], K)
`

### PULSE (>>)

`
⟨Pulse(из, в), (S, R, K)⟩ → (S, R[в ↦ R(из)][из ↦ Ничто], K)
`

Владение перемещается: источник обнуляется.

### PERFECT_LOCK

`
⟨PerfectLock(r), (S, R, K)⟩ → (S, R[r ↦ Совершенное(unwrap(R(r)))], K)
`

где unwrap снимает одну оболочку Совершенное, если она уже есть (идемпотентность фиксации).

### CALL / RET

`
⟨Call(f), (S · a₁ · … · aₙ, R, K)⟩ → (ε, R_f[0↦a₁,…], K · F_f)
⟨Ret, (S · v, R_f, K · F)⟩ → (S' · v, R', K)
`

## 4. Инварианты

### Инвариант 1: Типовая безопасность

Для любого перехода σ → σ', если σ типизировано, то σ' типизировано.

**Набросок доказательства:** каждое правило перехода проверяет типы входов и производит значение правильного типа (см. zip-verify / типы.rs).

### Инвариант 2: Отсутствие гонок данных

Состояние имеет **уникальных владельцев** для каждого линейного значения.

При PULSE (>>):

- владелец теряет ссылку;
- новый владелец получает значение;
- никогда два живых владельца одновременно.

**Набросок доказательства:** Move-семантика обнуляет источник (R(из) := Ничто).

### Инвариант 3: PERFECT-инвариант

Если  = Совершенное(w), то:

- содержимое w не модифицируется на месте;
- допустимы только чтение / перемещение оболочки;
- повторный PerfectLock идемпотентен.

**Набросок доказательства:** нет инструкции, которая пишет внутрь Совершенное без снятия оболочки; zip-verify запрещает Store поверх Совершенное.

### Инвариант 4: Согласованность стека

В любой достижимой точке |S| соответствует балансу push/pop инструкций до этой точки (с учётом ветвлений — over-approx по путям).

**Набросок доказательства:** индукция по длине трассы; статический анализ в zip-verify проверяет отсутствие pop с пустого стека.
