# R1. Polonius — улучшенный анализ владения импульсами

## Основание

В Rust Polonius — borrow checker на основе origin/path-sensitive анализа
(вместо чисто lexical lifetimes). Для ZIP та же идея применяется к
импульсам и оператору `>>`.

## Применение в ZIP

| Операция | Эффект на владение |
|----------|-------------------|
| `>>` (`Импульс`) | источник → Передан, назначение → Владеет |
| Аргумент `Вызвать` | move (Владеет → Передан); PERFECT только читается |
| `Переместить` / `=` | копия — источник сохраняет владение |
| `!` (`Зафиксировать`) | Владеет → Завершён |

Анализ — прямой dataflow по CFG (метки, `Перейти`, ветвления).
На join-точках используется meet: если на любом пути регистр передан,
после слияния он считается переданным (как в Rust).

## Пример

```zip
функция главная() {
    данные = 10
    САПАР(данные) >> ЧАТАВ!
    САПАР(данные) >> ЧТВ!  // ← ошибка: данные уже переданы
}
```

Диагностика:

```
Найдены ошибки владения:
  Регистр r1 уже передан через >> и не может быть использован (точка N)
    💡 Используйте оператор перемещения `Переместить` для копии
    путь передачи: …
```

## Флаги

```bash
zipc программа.zip -o выход          # анализ включён
zipc программа.zip --без-владения    # отключить (отладка)
```

## LSP

`зип-lsp` прогоняет тот же анализ после генерации IR и публикует
`DiagnosticSeverity::ERROR` с префиксом «Владение:».
