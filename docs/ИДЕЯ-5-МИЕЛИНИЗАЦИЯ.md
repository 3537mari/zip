# Идея 5. Миелинизация — JIT-компиляция горячих циклов

## Основание

В мозге миелин ускоряет передачу сигналов по часто используемым
нейронным путям. Аналогично, ZIP компилирует горячие функции в
нативный код через LLVM (clang).

## Подход (MVP)

Полный LLVM ORC (`llvm-sys`) на Windows недоступен без SDK
(`llvm-config` отсутствует). Используется **подход B**:

1. Байт-код → текстовый LLVM IR (`zip-vm/src/байткод_в_llvm.rs`)
2. `clang -O3 -shared` → `.dll` / `.so`
3. `libloading` (LoadLibrary / dlopen) → адрес символа `zip_fn_N`
4. VM вызывает `extern "C" fn(i64,i64,i64,i64) -> i64`

## Как работает

1. Идея 4 (Пластичность) считает вызовы и при пороге помечает функцию горячей.
2. JIT генерирует IR (регистры + стек, базовые блоки по PC).
3. clang собирает разделяемую библиотеку с `dllexport`.
4. Последующие `Call` идут в нативный код прозрачно.

Отключение: `ZIP_JIT=0` или отсутствие `clang` в PATH —
VM продолжает интерпретацию без падения.

## Синтаксис

```zip
@пластичность(порог = 3)
функция горячий_цикл(н) {
    сумма = 0
    для и в 0..н {
        сумма = сумма + и * и + 1
    }
    возврат(сумма)
}
```

## Прирост производительности

| Режим | Скорость |
|-------|----------|
| До JIT | интерпретация байт-кода |
| После JIT | нативный `-O3 -march=native` |
| Цель | ×20–100 на горячих циклах |

## Ограничения MVP

- Leaf-функции (без `Call` / `Print` / choir внутри JIT-тела).
- До 4 аргументов `i64`.
- Компиляция clang синхронна при первом пересечении порога.

## Пример

См. `examples/миелинизация_демо.zip`.

```bash
zipc examples/миелинизация_демо.zip -o миелинизация --байткод
zip-vm миелинизация.zipc
```

Ожидаемые логи:

```
🔥 Функция N (горячий_цикл) стала горячей (...)
[JIT] Планирование перекомпиляции функции N
[JIT] Функция N (...) скомпилирована → ...
[JIT] загружен нативный код функции N
```

## Статус

✅ MVP (октябрь 2026): clang -shared JIT, прозрачная замена Call.
⏳ Далее: in-process ORC, JIT вложенных вызовов, компиляция циклов без порога вызовов.
