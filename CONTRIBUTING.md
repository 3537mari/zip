# Как внести вклад в ZIP

Спасибо за интерес к ZIP! Мы рады любому вкладу: код, документация,
переводы, тесты, сообщения об ошибках.

## Способы внести вклад

### 1. Сообщить об ошибке

- Проверьте [существующие issues](https://github.com/3537mari/zip/issues)
- Если нет — создайте новое
- Опишите: что ожидалось, что произошло, как воспроизвести
- Приложите код и версию ZIP

### 2. Предложить улучшение

- Откройте [Discussion](https://github.com/3537mari/zip/discussions)
- Опишите идею
- Обсудите с сообществом

### 3. Написать код

1. Форкните репозиторий:
   ```bash
   git clone https://github.com/<ваш-username>/zip.git
   cd zip
   ```
2. Создайте ветку:
   ```bash
   git checkout -b feature/новая-функция
   ```
3. Внесите изменения
4. Убедитесь, что тесты проходят:
   ```bash
   cargo test --manifest-path zipc/Cargo.toml
   cargo test --manifest-path zip-vm/Cargo.toml
   ```
5. Сделайте коммит:
   ```bash
   git commit -m "Добавлена функция X"
   ```
6. Запушьте:
   ```bash
   git push origin feature/новая-функция
   ```
7. Откройте Pull Request

### 4. Улучшить документацию

- Опечатки, ошибки — исправляйте сразу
- Новые разделы — сначала обсудите в Discussion
- Переводы — приветствуются

### 5. Написать пример на ZIP

Примеры живут в `examples/`. Хороший пример:

- Решает одну задачу
- Хорошо документирован
- Работает без изменений

## Стандарты кода

### Rust-код (компилятор)

- Форматирование: `cargo fmt`
- Линтинг: `cargo clippy -- -D warnings`
- Имена на русском (для API ZIP) или английском (для инфраструктуры)

### ZIP-код (STD, примеры)

- Только кириллица
- Комментарии на русском
- Стиль: см. существующие файлы

### Документация

- Markdown
- UTF-8
- Кириллица разрешена

## Процесс review

1. Автоматические проверки (CI)
2. Ревью мейнтейнера
3. Если нужно — правки
4. Merge
