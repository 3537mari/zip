# Управление проектом ZIP

## Модель управления

ZIP использует модель **Benevolent Dictator for Now (BDFN)**:

- Есть главный мейнтейнер
- Есть команда контрибьюторов
- Решения принимаются консенсусом, где возможно

## Роли

### Главный мейнтейнер

- Финальное слово по архитектуре
- Мерж PR в `master`
- Релизы

### Мейнтейнеры

- Review PR
- Мерж PR в `develop` (если ветка используется)
- Обсуждение архитектуры

### Контрибьюторы

- Написание кода
- Документация
- Тесты
- Примеры

### Сообщество

- Issues
- Discussions
- Помощь другим

## Как стать мейнтейнером

1. Активное участие 3+ месяца
2. 10+ качественных PR
3. Понимание архитектуры
4. Голосование существующих мейнтейнеров

## Процесс принятия решений

### Мелкие изменения

1. PR от любого контрибьютора
2. Review одним мейнтейнером
3. Мерж

### Средние изменения

1. Discussion
2. Согласие 2+ мейнтейнеров
3. PR + review

### Крупные изменения (RFC)

1. Создание RFC в `rfcs/`
2. Публичное обсуждение 2 недели
3. Голосование мейнтейнеров
4. Реализация

## Релизы

- **Major (X.0.0):** несовместимые изменения
- **Minor (0.X.0):** новые функции
- **Patch (0.0.X):** баг-фиксы

## Лицензия

MIT — все изменения под той же лицензией.
